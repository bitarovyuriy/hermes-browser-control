# Changelog

All notable changes to the Hermes Browser Extension (MV3) are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);
versioning follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Versions map to Chrome Web Store channels:

| Version range | Channel | Store listing | Audience |
| --- | --- | --- | --- |
| `x.y.z` | stable | public | everyone |
| `x.y.z-beta.N` | beta | unlisted / trusted testers | opt-in testers |
| `x.y.z-dev.N` | dev | "load unpacked" only | contributors |

## [Unreleased]

### Fixed

- `tools/install-native-host.mjs`: the unpacked-extension id is now derived host-independently.
  A Windows-shaped path (`C:\…`, `C:/…`, a UNC share) is normalised with `path.win32` and hashed
  as UTF-16LE — what Chrome hashes on Windows — while a POSIX path is hashed as UTF-8. Before,
  `path.resolve` re-rooted `C:\example\extension` into the runner's working directory on Linux,
  so the pinned Chrome vector (`khljnbaehneoiakcfkbmegihfaokaboc`) failed in CI while passing on
  Windows. The id for a real Windows install is unchanged.

## [0.3.0] - 2026-10-08

The side panel is gone: the extension is a bridge for the Hermes runtime, and the only
page it ships is the human stop.

### Removed

- `side_panel` in the manifest and the `sidePanel` permission — driving the browser never
  needed a panel, and the side panel was the only consumer.
- The panel's command box and `src/panel-commands.js` (the command-line parser existed
  only for that box). Commands now enter through `hermes/command` on the worker's message
  surface, which is the relay's entry point.
- The panel's relay form (mode / port / base URL / pairing string), tab grant list, tab
  list and artifact feed. Pairing for a human is the native host's job; a manual
  `hbr1:` string survives as a `hermes/relay` action for tooling.
- Arm-by-click buttons: the session auto-arms (`agent-all` over the relay, `tab-group`
  when the agent opens its own tab).

### Added

- An icon set — `extension/icons/icon-{16,32,48,128}.png`, the black-on-white line art kept
  as drawn (opaque white plate, so it holds up on a dark toolbar too), generated by
  `tools/make-icons.py` from `release/assets/icon-source.png`, plus the `icons` /
  `action.default_icon` manifest blocks. The store needs a 128×128 icon and the browser showed
  a puzzle piece without one.

### Changed

- The toolbar click opens a **popup** (`control/popup.html`, `action.default_popup`) instead
  of a tab; the `chrome.action.onClicked` → `openOptionsPage()` handler that did that is
  gone. The same page is still the extension's options page (`control/control.html`), and
  the popup links to it ("Open as a full page"). No new permission is needed for either.
- `panel/` → `control/` (`control/control.html|js|css`) and the manifest now declares it
  as `options_ui` (`open_in_tab`), opened by the toolbar action via
  `chrome.action.onClicked` → `chrome.runtime.openOptionsPage()`.
- The control page was redrawn as a monochrome readout — ink on paper, hairline rules, one
  segmented control grid, a monospaced log. No colour, no rounded cards, no fills behind
  content; the palette is black, white and two greys. The toolbar popup and the options page
  are the same page at two sizes.
- The control page is state + Pause / Resume / Reconnect / Kill switch, talks to the
  worker only over `hermes/state` / `hermes/relay`, and polls it every 2 s so a worker
  restart cannot leave a stale `armed` on screen.
- The E2E harness drives the worker's message surface instead of a page (42 checks), and
  drops its own transport session first: on a machine with the native host installed, the
  worker's boot-time pair would otherwise land on the user's live relay and auto-arm it.
- `test/unit` 66 → 60 tests (the `panel-commands` suite went with the command box);
  `test/e2e` 39 → 42 checks, `test:relay` 42 → 41.

## [0.2.0] - 2026-10-08

The merged MVP: one loadable MV3 extension that combines the three shipping
workstreams — CDP browser control (the carrier), the loopback relay transport, and
the operation guard on the live command path.

### Added

- **CDP browser control (carrier).** `chrome.debugger`
  attach with CDP command forwarding (`src/cdp-methods.js`, `src/controller.js`),
  the banner-free content-script path for loopback origins
  (`content/content-script.js`, `src/fallback.js`), access modes and tab leasing
  (`src/access-policy.js`), session state armed/paused/killed
  (`src/session-state.js`), artifacts (`src/artifacts.js`), the side panel
  (`panel/`), and the pure command router (`src/command-router.js`).
- **Loopback relay transport.** `extension/vendor/transport/*`
  (pairing, WS session, backoff, heartbeat, command queue, redacting logger)
  wired into a single worker-side host, `src/relay-host.js`.
- **Operation guard on the live command path.**
  `security/operation-guard.mjs` + `lib/sensitive-domains.mjs` (the single sensitive
  rule list), wired by `src/admission.js` before `planCommand` so a denied command
  never reaches the CDP or content path.
- Store listing, privacy policy, permission justifications and the release toolkit
  under `release/`.

### Security

- **Deny-list, both paths.** The target URL (the `navigate` target, otherwise the
  tab's current URL) is classified by `lib/sensitive-domains.mjs`: banking, crypto,
  password managers, email, government/tax, medical, credential surfaces and
  checkout are refused with `code: sensitive-domain`; an unparseable URL is refused
  too.
- **Fail-closed freshness lease (relay path).** `handleStatus` registers the live
  `{profileId, port}` binding; arming a session copies it into the lease. A relay
  command whose lease no longer matches the live binding is refused with
  `stale-port` / `stale-profile`; without a binding the relay path fails closed
  (`no-lease`).
- **Narrow permissions.** `debugger, tabs, tabGroups, storage, alarms,
  nativeMessaging, sidePanel`; the only host permissions are loopback
  (`http://127.0.0.1/*`, `http://localhost/*`). No `<all_urls>`, no `activeTab`,
  no `scripting`, no `contextMenus`.
- **No remote code.** Every script ships inside the package; there is no `eval`,
  no `new Function`, no remotely fetched script.
- Secret scanner (`security/scan-secrets.mjs`) runs as a required CI gate.

### Known limitations

- Firefox has no `chrome.debugger` equivalent — chat only, no tab attach.
- The content-script (banner-free) path is declared for the loopback origins only;
  arbitrary user tabs go through the CDP path, which is why `debugger` is requested.
- `chrome.debugger.attach` fails with `debugger-busy` when DevTools is already
  attached to the same tab.
- The native-messaging host is not registered on this machine yet, so `local` mode
  pairs from a manual string (or `HERMES_RELAY_URL`) until the Hermes installer
  writes the host manifest.
